# Language feedback

What writing Ernest felt against the principles, a line each, carried to Ernest as `CLAUDE.md`'s *The work* says. These come from the template's full review at `d8b7ab4` with `ern 0.11.0+93a13b13`, by their findings in `findings.md`.

- **`ern doc` overwrites a root module named `index` in silence** (KE1). A module src/index.ern beside another, then `ern doc src`: status 0, and the page of the module `Index` is the listing, which links to itself. Principle 3. Ask: refuse the module, or name the listing so that no module can take its name.
- **`ern doc` writes its pages where the `.erc` stand** (KE2). The template sifts the `.md` out of the build root by `find`, which lost a module's page named `index` (K7). Principle 2. Ask: `--doc-root dir`.
- **No `List.findIndex`** (KE3). `List.find` and `List.indexed` stand beside it, and the program writes `Optional.map(List.find(List.indexed(list), …), fn(#(index, _)) = index)`. Principle 1. Ask: `List.findIndex : (List(a), (a) -> Bool) -> Optional(Int)`.
- **`ern format --check` says a bare path** (KE4). Only the Makefile's echo told the reader that the path meant "not laid out". Principle 3. Ask: each line says what is wrong, `src/name.ern: not laid out`.
- **`ern format` hangs a long call's arguments under its bracket** (KE5). A test of one expression began its body at column 46, and the style guide's answer, naming a part, does not fit a test of one expression. Principle 1. Ask: a long call's arguments laid out one a line at the block's indentation.
- **The 0.11.0 candidate's `CHANGES.md` stops at 0.10.0** (KE6, C49, DE1). Its README is headed Ernest 0.11.0, and nothing in the installation says when `ern unpack` and §11.9 came. Principle 1. Ask: the release carries its section of `CHANGES.md`.
- **The guide points outside the installation** (KE7). Guide §7.1 sends the reader to a page of Ernest's repository for what a module's documentation holds. Principle 3. Ask: the guide states it, or the installation holds the page.
- **`Markdown.parse` gives no block its line** (C47). A tool that reports a file and a line cannot use Ernest's CommonMark reader, so `tools/docs.ern` reads Markdown itself, and misses a lone backtick and a fence longer than the one it quotes (C13). Principle 2. Ask: each block's line, counted from 1; the checker then reads by `Markdown.parse`.
- **`ern test` runs a `.erc` under a path `ern build` refuses** (C48). `ern build src` refuses a directory `v-1.0`, while `ern test out` runs out/v-1.0/a.erc. A failed release leaves a staged copy of `build/` inside the build root, and `make test` then runs every test twice. Principle 1. Ask: `ern test` holds the path's shape as `ern build` does.
- **The report is silent on `priv` outside a named package** (DE2). §11.9 says the host finds a named package's `priv` beside its `ebin`; nothing says so of an application under `--libs-dir` or an `ebin` that `--load-path` names, and the launcher rests on both. Principle 3. Ask: a sentence in §11.2.
- **A compiled program cannot be carried to another build of `ern`** (DE3). §11.2 refuses every `.erc` that another build wrote, a patch release's among them, and an installation holds no source; the review fixes the template's `make install` to build first. Principle 1. Ask: a rule for a patch release, or a sentence in the deployment guide that an installed program is built by the `ern` that runs it.
- **A configuration directory has no customary name or place** (DE4). Neither the report nor the deployment guide gives one, so a repository cannot keep a node's key out by name; the review fixes the template to ignore `private-key.pem`. Principle 1. Ask: a sentence in the deployment guide on keeping a configuration directory out of a checkout.
- **`ern doc --man` titles a library's module as Ernest's** (SE1). The template's module `Name` gets the page `Ernest.Name.3ern`, headed `Ernest.Name` in "Ernest Manual". Principle 1. Ask: a module outside Ernest's own titled by its own name, and its manual by its package.
