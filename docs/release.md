# The release

What a release runs to be ready, and nothing else. Between releases a change runs `make test` before every commit (CLAUDE.md, *Tests*).

1. **A fresh clone builds and passes:** `git clone`, with `--recursive` where there is an `erl/`, then `make test`, in a directory of its own.
2. **Two readers**, each a session of its own, the code reader on the most advanced model and the cold reader on the one below, since it reads as a user and judges no rule; each given its brief and the files it reads, and nothing that argues for them: a cold reader, who reads `README.md` and runs the program as a user would; and a code reader, who reads `src/` against `design.md`, the report's §0 and Appendix E.0's shape rules. Each hands in a numbered list, most serious first: a finding gives its place, a short quote, what is wrong, and a one-line fix.
3. **The findings:** a defect is fixed or planned in a milestone; clarity is fixed where it is cheap, and otherwise dropped. The lines stand in `findings.md` until each is done, and the commit messages say which. A decision among them is argued after the log is searched for the decision it may sharpen (CLAUDE.md, *Before code*), and a name a reader lists is decided after the word is searched across the design, the code and the pages, never from its module alone.
4. **The round:** once the findings are fixed, the cold reader again over the diff from the commit the review started on to the release's commit, the lines the review's own fixes wrote and no reader has read.
5. **The release:** `VERSION` set; for a library, every exported declaration that appeared since the last release ending its doc block with its own `since`, and the pages `make man` writes into `docs/man/`, committed with the release; the tag; and the archive `make release` writes, `build/<name>-<version>.tar.gz`, published beside the tag so that another repository's `make lib` can name it.
6. **The note**, the release's section of `CHANGES.md`, first in the file and committed before the tag, which the release step copies as the notes of the release on GitHub so that it is written once: what the release is, what a program or an operator of the previous release changes, one line a change naming where it is read, the design's section or the log's entry, and beneath them the design's diff between the last release's tag and this one's and the log's entries since; it restates no change.
7. **`language_feedback.md`'s lines carried to Ernest**, so that a release leaves nothing the language has not heard.
